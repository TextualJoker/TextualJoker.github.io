    The bug was two numbers swapping places. A book cover, rebuilt from code that had not changed, came back different — 408,395 of its 462,074 bytes. That reads like a re-encode, and I wrote it up that way.

    It was not. Compared object by object instead of byte by byte, one thing moved. Each image in a PDF points at its transparency mask by object number, and the two had traded: front got 17, back got 16, then the other way round. Both decompressed identically. The 408,395 was two objects of unequal size swapping order and shoving the rest along.

    The cause is a race: the library decodes each image asynchronously and numbers the mask when that finishes. One image races nothing. Which killed the rule I wrote the night before — covers flap because they carry images, interiors are pure vector. Interiors are not. Every one carries a raster. The real line is one image versus more than one.

    Lesson A byte count tells you how far a difference spread, not how big it is. Diff the structure before you believe the size.
